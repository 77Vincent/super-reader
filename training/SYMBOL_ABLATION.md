# 保留符号／纯文字输入 smoke

2026-09-29。比较两种输入表示能否改善当前模型的断点预测。
正式模型和插件推理规则保持不变。

## 两组设置

- `context`：当前 `unicode-context-v1` 输入，保留非 proxy 符号和普通空格。
- `text-only`：在已经清洗、隐藏目标 proxy 的 A/B 中，仅保留汉字、
  ASCII 英文字母 A–Z/a–z 和 Unicode 十进制数字；删除标点、其他符号及空格。
  A 和 B 分别投影后重新计算目标，禁止把删除的字符算进新的目标坐标。
- 两组使用相同的 100 万条原始训练样本，固定验证／测试子集各 10 万条。
  样本取自现有 v7 清洗结果，不修改 proxy、质量规则、文档划分或屏障。
- 按当前 3.9626621 亿样本的来源占比分配训练配额；在各来源内随机选择
  既有 hash 分片，再对分片池做固定种子的 reservoir 抽样。
  这属于两阶段抽样，不宣称是对全部训练行的精确均匀抽样。
- smoke 排除原始长度超过 256 个 Unicode 字符或投影后任意一侧为空的样本，
  两组同时排除。验证先抽取；测试排除与抽中验证集投影后输入相同的行；
  新训练排除与抽中两套 holdout 投影后输入相同的行，不论目标是否相同。

两组都从当前正式模型的 `epoch-1-backend/best_state` 独立初始化：
192 通道、16 层卷积、8,192 词表、修复 padding 的 FP32 Metal 实现。
词表与 token ID 不变，使用新的 AdamW，学习率 `0.00003`，weight decay
`0.0001`，梯度裁剪 `1.0`，每组固定训练 1 epoch。

原始长度／位置权重、domain^-0.65 权重在两组相同，不随删除字符重新计算。
同样的种子、原始长度分桶、样本次序和批次划分保证样本曝光及更新次数一致。
batch 上限 512，token 预算 8,192。批次补齐到原始长度桶的上限，
两组 padded shape 相同；沿用每层屏蔽 padding 的正式模型实现。

## 如何判断结果

不只比较各自全部候选位置上的 top-1：删符号会减少候选数、改变任务难度。

1. **原生 top-1**：各自全部 token gap 的准确率，以及平均候选数、随机基线。
2. **共同候选 top-1**：只比较原文中两个相邻字符都被保留的 gap。
   两组使用完全相同的原文候选位置；目标不在共同集合中的样本不进入此指标，
   并报告覆盖数量。删除引号后跨过引号形成的新 gap 不在这个集合内。
3. 分别报告全体、确实删除了字符的样本、原本就为纯文字的样本；
   另按 domain 及删除字符类别细分。
4. 先完成两组固定 epoch 终点及验证，再测两个终点的测试表现。
   不根据测试成绩挑检查点，不将未改善的终点偷偷替换成初始化。

同时保留训练前验证结果，以区分立即改变输入造成的影响和短训练后的适应。
这是单种子、从已习惯带符号输入的模型继续训练的短实验，不能代表两种表示
从头充分训练后的上限。holdout 在历史实验中已经使用，也不是新的盲测集。
本轮排除了新训练与抽样 holdout 的投影重合；继承权重的全部历史训练曝光
未在纯文字表示下重新审计。

代码快照和模型权重保留；下面的恢复命令要求完整数据，不能直接恢复这个
已清理目录。需要重跑时使用新的 `--run-dir` 重新准备数据。

```sh
python3 training/run_symbol_ablation.py
python3 training/run_symbol_ablation.py --resume
```

向协调器发送 SIGTERM 可在安全边界暂停；确认状态为 `stopped` 后再关机。

准备阶段中断会重新抽样；评估阶段中断会从头重算本次评估。

`run.json` 固定数据、初始权重和代码快照的哈希；最终 `comparison.json`
与 `comparison.md` 保存两组结果；每次评估另有逐样本预测的 `.npz`。

预检：7 项 `test_symbol_ablation.py` 测试通过；两组分别在 Metal 上完成
128 条训练／32 条评估夹具。恢复已完成训练后，更新次数不增加，重新计算的
验证结果相同。

## 已完成结果

两组均完成 1,000,000 条样本、5,310 次参数更新。保留符号组纯训练耗时
232.00 秒，纯文字组 229.09 秒；这里不包括准备、评估和检查点开销，
也不能用相同 padded shape 的 smoke 推断缩短输入后部署时的速度上限。

测试子集结果如下，均为准确恢复隐藏 proxy 的 top-1，单位为百分比。
共同候选覆盖 96,371／100,000 条；其中含被删除字符的样本为 33,479 条。

| 测试指标 | 保留符号 | 纯文字 | 纯文字变化（百分点） |
|---|---:|---:|---:|
| 全体，各自原生候选 | 89.5680% | 83.8740% | -5.6940 |
| 全体，相同原文候选 | 89.8995% | 88.4364% | -1.4631 |
| 原本含被删除字符，相同原文候选 | 89.2589% | 86.1197% | -3.1393 |
| 原本纯文字，输入及候选均相同 | 90.2404% | 89.6696% | -0.5708 |

在共同候选测试的 96,371 条中，纯文字组单独命中 947 条，保留符号组
单独命中 2,357 条，净差 1,410 条。验证集同样退步：共同候选准确率
89.8370% → 88.3583%，原生准确率 89.4950% → 83.8120%。

训练前直接把输入变为纯文字时，验证原生准确率为 83.5150%，共同候选
88.8249%；这轮适应训练略微改善了原生指标，但共同候选指标还略有下降。
不能把这轮结果概括为“删符号后只需要多适应一点就一定能追上”。

### 删除符号会制造额外的竞争位置

测试中纯文字组的 16,126 个原生预测错误里，有 5,909 个预测落在删除
符号或空格后新形成的相邻字符间。其中 4,803 条是保留符号组原本命中的。
例如同一原始 A/B：

```text
老师及保留符号组：同样的环境、同样的管理｜不同的就是肥料对比
纯文字组：        同样的环境｜同样的管理不同的就是肥料对比
```

顿号被隐藏后，那里也变得像一个待恢复的断点。这里的“错”是没恢复原
proxy 标签，不意味着这个位置完全不符合人类停顿习惯；这恰好说明只删
字符却保留唯一目标，可能增加输入歧义。把新增位置排除后，纯文字组仍然
较弱，因此本轮退步也不能全部归因于新增候选。

### 结论与边界

**当前没有证据支持全量删符号，保留现有输入策略。** 两组均从当前模型
继续训练，纯文字表示发生变化；这是一轮 100 万条、单种子、固定低学习率
的短续训结果，不能推出从头训练、充分适应后的纯文字模型上限更低。
本轮同时删除标点、空格和其他非保留字符，也没有分别隔离它们的影响。

训练样本中 37.7938% 的输入发生变化，总字符数减少 3.9018%。独立遍历
此次准备的 120 万条数据确认：投影后无跨集合相同输入；训练内有 1 条
投影重复，无冲突目标。正式模型文件 SHA-256 与实验启动前相同，没有
发布任何实验权重。

完整结果与可复核文件位于上述输出目录：

- `comparison.json` / `comparison.md`：两组起点、终点、测试、分域指标。
- `projection-audit.json`：投影后的跨集合重合与标签检查。
- `examples.md`：固定种子抽取的两组分别命中实例。
- `new-gap-errors.json`：新增相邻位置的事后错误计数及实例；不用于选模型。
