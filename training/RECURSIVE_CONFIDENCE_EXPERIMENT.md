# 90% 门槛下的递归重新评分

2026-09-15：实验能够产生通过门槛的第二刀，但这批文本的新增收益有限。
21 组案例、26 个文本节点中，切分点从 **11 增至 12**，只有当前 demo 的第一段变化；
Chrome Worker 整组处理耗时中位数从 **701.0 ms 增至 895.5 ms（+27.7%）**。
重新运行 CNN 的递归方式作为可选实验入口保留。

后续改动：后端已移除位置加权，合格切点直接按原始 logit 排序。以下保留实验当时的
设置与测量；重新运行脚本会使用当前后端规则。正式默认已改为
[75% 递归 softmax](RECURSIVE_SOFTMAX.md)，复用原始 logits。

## 控制变量

两者使用同一份正式 16 层、192 通道 epoch 1 权重，同样严格要求概率 >90%。
输入、标点预分句、12 视觉单位门槛、NFKC token、词语/数量/时间/标点保护、
256-token 窗口和平衡规则一致。词语保护在原始子句上只计算一次，避免子句分词变化
成为额外变量。所有结果都保留原文和原始 UTF-16 偏移。

- 单次评分：原始子句推理一次，后续片段复用原 logits 和原概率。
- 递归评分：第一刀完全相同。对仍超过 12 单位的左右片段分别重新推理，并根据
  新 logits 在该片段全部 gap 上重新计算 softmax；只有通过 90% 和保护规则才继续切。

递归版使用显式栈处理左右片段；子片段概率来自新的模型前向计算。
不同窗口的分数合并后再归一化，短尾窗口不会单独产生必选位置。

## 结果

固定核心集沿用上次置信度比较的 16 组、20 个文本节点。
补充数据库截图片段、“能够更加轻松地找到句子中的重点”，以及当前 demo 的 3 段、
4 个文本节点，合计 21 组、26 个节点。demo 中的加粗内容按独立文本节点处理。

| 范围 / 指标 | 单次评分 >90% | 递归评分 >90% |
| --- | ---: | ---: |
| 原有 16 组：切分点 | 7 | 7 |
| 原有 16 组：模型调用 | 17 | 21 |
| 全部 21 组：切分点 | 11 | 12 |
| 全部 21 组：模型调用 | 25 | 32 |
| 全部 21 组：累计模型输入 tokens | 507 | 648 |
| 全部 21 组：Node 耗时中位数 | 656.34 ms | 838.20 ms |
| 全部 21 组：Chrome Worker 耗时中位数 | 701.0 ms | 895.5 ms |

唯一新增的第二刀来自当前 demo 原文：

```text
单次：因此｜过长的的句子会破坏阅读体验。
递归：因此｜过长的的句子｜会破坏阅读体验。
```

第二次输入是 `过长的的句子会破坏阅读体验`；新增切点置信度 **91.34%**。
同一位置在原子句概率分布中仅占 **0.90%**，说明不同层级的相对概率不能直接比较。

其他关注案例：

- `也希望阅读的时候｜能够更加轻松地找到句子中的重点。`：第一刀 98.27%；
  剩余片段重新评分的最大概率为 **43.16%**，停止，保持“句子中的重点”完整。
- `实验结果表明｜该方法能够有效降低复杂环境下的预测误差。`：后半段最大概率
  **69.12%**，停止。
- `币安数据库里的一条记录（IOU/欠条）`：第一轮最大概率 **45.08%**，两种策略
  都不切分，也不会进入子片段递归。

## 验证和解释范围

200 项测试通过。新增测试检查确实重新推理、第二刀可改变位置、低信心子句停止、
原有词语保护不变、右侧索引映射、长窗口和补充 Unicode 字符的源偏移。
实验逐项断言第一刀相同、旧切点保留、每个新切点通过门槛、原文不变。
Chrome 152 中两种策略的全部输出都与 Node 一致；生产默认 Worker 的检查也通过。

两种策略各预热 2 遍、测量 9 遍，交替 AB/BA 顺序。Node 还交替案例顺序；
Chrome 在同一隔离 Worker 中处理完整 26 节点视口。计时不含首次模型加载、DOM 或
浏览器消息往返。正式 epoch 2 训练同时继续运行，因此耗时用于这次同条件比较。

这批文本没有人工完整切分标签，不能计算递归第二刀的 precision/recall。
上次全量验证的 **98.08%** 不能直接用于后续子句：模型仍按每条输入一个目标断点训练，
没有“不需要切分”的标签。这里确认了递归机制可工作，并记录了额外调用成本；
尚不足以判定真实阅读质量全面提高。

`scoringStrategy: "recursive-softmax"`，门槛为 75%。
