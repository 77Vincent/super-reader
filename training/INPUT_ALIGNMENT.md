## 工作原理

训练从相邻合格片段 `A，B` 隐藏中间 proxy，得到输入 `AB` 和目标 `A｜B`。
推理先按现存 proxy 分出片段，把其中足够长的片段视为可能的 `AB`，
寻找内部切点。无需在真实输入中重新拼接已经有标点的两个片段。

需要一致的是：原始 proxy 的识别、数字例外、字符归一化、保留的上下文和换行屏障。
语料中的首片段舍弃、质量过滤、目标合法性等用于选择训练老师；
不把这些规则复制成删除网页内容的操作。

## 具体修复

| 项目 | 修复前 | 修复后 |
| --- | --- | --- |
| Proxy 集合 | 中英文逗号、句点、分号、问叹号等混用 | 仅原始中文 `，。；！？…`；英文标点保留为上下文 |
| 处理顺序 | 先 NFKC，再判断 proxy | 先识别原始 proxy，再归一化片段；`﹐` 保留成 `,`，`｡` 保留成 `。`，不因归一化新增屏障或丢 token |
| 顿号 | `、` 及兼容形式另行预分段 | 移除额外预分段；与训练相同，作为模型上下文保留 |
| 数字逗号 | 只检查左右紧邻数字字符 | 与训练同样识别正负号、小数、科学记数法及周围空白；`(-8545，-27679)` 整体归一化为 `(-8545,-27679)` |
| 换行 | 折成空格，可能把两行一起推理 | 所有训练物理换行都先隔断；包括 CRLF、NEL、Unicode 行／段分隔符，不跨行拼接 |
| 引号／括号 | 将 proxy 后的闭合符号移入上一片段 | 保持原始 proxy 划分的字符归属；`他说：“明天见。”然后离开。` 的第二个模型输入以 `”` 开头，与训练提取一致 |
| 长句窗口 | 256-token 窗口只重叠一个 token，交界处缺上下文 | 每个所负责的 gap 额外携带完整卷积上下文；当前左右各 16 token，窗口仍不超过 256，每个 gap 只保留一个分数 |

页面原文、标点、空白和字符宽度都保留；返回切点继续使用原始 UTF-16 坐标。
现有超过 12 个视觉单位才处理、汉字相邻保护、浏览器词内保护、递归 softmax
均不改变。超过 256 token 的子句增加了重叠上下文计算，较短子句仍只推理一次。
